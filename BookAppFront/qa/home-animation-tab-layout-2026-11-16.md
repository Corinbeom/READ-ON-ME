# 메인 타이핑 깜빡임과 탭 화면 규격 (2026-11-16)

> 이 문서는 당시 변경과 측정 기록이다. 후속 [UI 규격 리팩터링](ui-consistency-2026-11-16.md)에서 좌우 여백은 24px, 콘텐츠 하단 여백은 32px, 탭 클릭 높이는 64px로 갱신했다.

## 원인과 변경

메인의 타이핑 문자열과 커서 상태가 `HomeScreen`에 있어 글자 변경마다 홈 전체가 렌더링됐다. `BookCarousel`의 `renderBookItem` 안에서 `BookContent` 컴포넌트를 매번 정의해 React가 같은 책 표지를 새 컴포넌트로 처리했다.

- 타이핑·커서 상태와 타이머를 `HomeAiPrompt`로 분리했다. 탭을 벗어나면 타이머를 정리한다.
- 카드 내용은 JSX 값으로 렌더링해 부모가 다시 렌더링돼도 표지를 재마운트하지 않는다.
- 움직이는 예시 문구는 한 줄로 제한해 긴 문구 때문에 아래 목록이 밀리지 않도록 했다.
- 세 탭이 `TabScreen`·`TabHeader`와 `SCREEN_LAYOUT`을 공유한다. 웹 최대 폭 640, 좌우 여백 22, 제목 28/줄 높이 40, 웹 상단 여백 40, 하단 콘텐츠 여백 40을 사용한다.
- iOS·Android에는 공통 SafeAreaView의 위·좌·우 안전 영역과 헤더 내부 여백 16을 사용한다. 하단 탭은 높이 60에 실제 bottom inset을 더한다. 검색 자동완성의 좌우 여백도 검색 결과와 동일하게 맞췄다.

## 브라우저 검증

실제 Chromium과 실제 도서 API로 확인했다. 도서 데이터와 API 응답을 목으로 대체하지 않았다.

| 관측 | 결과 |
| --- | --- |
| 수정 전 공개 홈, 4초 | 텍스트 변경 28회, 표지 노드 추가 370·제거 370 |
| 수정 후 로컬 비로그인 홈, 4초 | 표지 10개 유지, 추가 0·제거 0, 서로 다른 문구 상태 18개, 첫 표지 top 351 고정 |
| 수정 후 로컬 로그인 홈, 4초 | 표지 20개 유지, 추가 0·제거 0, 문구 상태 24개, 첫 표지 top 351 고정 |
| 320·390·1280px × 홈·검색·서재 | 9가지 조합에서 화면 폭·중앙 정렬·22px 여백·제목 위치와 글자 크기 일치, 가로 문서 넘침 없음 |
| 390px 로그인 서재 | 실제 로그인 후 동일한 헤더·폭 규격 확인 |
| 일반 도서 검색 | `1984` 검색 20권 표시, 검색 결과에서도 헤더·폭 유지 |

390px·1280px에서는 세 탭 헤더 높이도 92px로 같다. 320px 비로그인 홈은 로그인·회원가입 버튼을 다음 줄로 배치해 헤더가 131px이고, 제목 자체의 위치·서체·여백은 다른 탭과 같다.

정량 관측은 Chromium 기준이다. 추가로 iPhone 16 Pro / iOS 18.2 시뮬레이터의 Safari에서 공개 홈의 타이핑·책 표지·탭 표시와 검색 화면의 헤더·입력창 배치를 확인했다. 최초 진입에서는 빈 화면이 한동안 보인 뒤 정상 표시돼, 초기 로딩 UX 개선 항목으로 남긴다. 실물 기기의 노치·키보드·글자 확대와 네이티브 Expo 앱의 변경 화면은 별도 확인이 필요하다.

## 자동 검사

- TypeScript, ESLint, 기존 프런트 테스트 3개 통과.
- 공개 API 주소를 지정한 `npm run build:web` 통과. 실제 브라우저 번들에 API 주소가 포함되고 Pages용 의존성 자산이 준비됐음을 확인했다.

## 공개 웹 반영

Cloudflare Pages 배포 `96bb7915`를 https://read-on-me-beta.pages.dev 에 반영했다. 공개 홈에서도 4초 동안 문구 상태 18개가 관찰됐고, 표지 10개는 추가·제거 없이 유지됐으며 top은 351px로 고정됐다. 공개 검색·서재도 390px 화면에서 동일한 규격을 확인했다.
