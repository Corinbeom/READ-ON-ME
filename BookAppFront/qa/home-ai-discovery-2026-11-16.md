# 홈 AI 사서 진입 개선 (2026-11-16)

## 화면과 동작

홈의 AI 사서 영역에 ‘오늘은 어떤 책을 읽고 싶으세요?’ 제목, 책갈피 캐릭터, ‘나에게 맞는 책 찾기’ 버튼을 배치했다. ‘위로가 되는 책’, ‘빠져드는 소설’, ‘짧은 에세이’ 예시는 추천 화면의 편집 가능한 조건으로 이어진다. 예시 선택 자체로 검색을 접수하지 않으며 사용자가 ‘책 찾아보기’를 눌러야 요청한다. 타이핑 예시의 높이는 고정하고 상태는 `HomeAiPrompt` 안에 유지했다.

- 홈과 추천 입력 화면은 `src/constants/aiSearchExamples.ts`의 예시를 공유한다.
- `prompt` 진입 조건은 최대 500자로 정규화한다. 새 조건은 완료된 이전 결과 대신 입력 화면으로 열린다. 일반 진입은 이전 추천을 복원한다.
- 이전 검색이 QUEUED/RUNNING이면 해당 검색을 먼저 표시하고 선택한 새 조건을 보관한다. 검색 종료 후 사용자가 명시적으로 새 입력 화면을 열 수 있다.
- 비로그인 화면에 선택한 조건을 보여준다. 로그인·회원가입 사이에서도 조건을 전달하며 로그인 후 추천 화면으로 돌아간다. 복귀 경로는 `ai-books`만 허용한다.
- 접수된 검색의 복원 정보를 저장한 뒤 진입용 `prompt`를 URL에서 제거한다. 새로고침하면 새 입력 화면 대신 접수한 검색과 결과를 복원한다.
- 로그인 화면을 정리하고 추천 화면으로 복귀해 뒤로 가면 홈으로 돌아오도록 했다. 직접 추천 URL을 연 경우에도 뒤로 가기 대체 경로를 제공한다.

## 검증

실제 로컬 Expo 웹과 Spring/AI API, 기존 테스트 계정으로 확인했다.

| 항목 | 결과 |
| --- | --- |
| 320·390·640·1280px 홈 | 문서 가로 넘침 없음. 주요 버튼 높이 48px, 예시 버튼 44px. 320px에서는 예시가 두 줄로 배치됨 |
| 세 예시 | 선택한 문구에 대응하는 전체 조건이 추천 입력창에 표시됨 |
| 비로그인 예시 → 가입 화면 → 로그인 화면 | 조건과 고정 복귀 경로 유지. 실제 신규 가입은 하지 않음 |
| 실제 로그인 후 진입 | 예시 조건이 편집 가능한 입력창에 유지됨. 기존 완료 결과가 덮어쓰지 않음 |
| 검색 접수 전 네트워크 | 예시 선택·인증·입력 화면 진입까지 AI 작업 접수 POST 없음 |
| 첫 명시적 검색 | 입력 조건을 수정한 뒤 실제 API 검색 접수 POST 1회. 결과 1권 확인 |
| 결과에서 새로고침 | 진입용 prompt가 제거된 URL에서 기존 결과 복원. 입력 화면으로 되돌아가지 않음 |
| 진행 중 새 예시 선택 | 두 번째 실제 검색 ‘소설 추천해줘’ 진행 중 ‘짧은 에세이’ 선택. 기존 검색과 새 조건 보관 안내를 표시하고 추가 접수 없음(구간 전체 POST 1회). 완료 후 보관한 조건의 입력 화면으로 이동 확인 |
| 로그인 후 뒤로 가기 | 추천 화면 → 홈 이동 확인 |
| 타이핑 회귀 | 4초 동안 이미지 21개 추가 0·제거 0, 타이핑 상태 19개, 첫 표지 top 576px 고정 |
| 다크 모드 | iPhone 16 Pro / iOS 18.2 시뮬레이터의 실제 Safari에서 홈 표시 확인 |
| 자동 검사 | TypeScript·ESLint 경고 0·테스트 11개 통과. 실제 공개 API를 지정한 웹 빌드와 폰트 시작 검사 통과 |

신규 유닛 테스트 6개는 URL 조건 정규화, 인증 복귀 경로 제한, 일반 진입 시 복원, 완료된 검색과 새 조건의 분리, QUEUED/RUNNING 보호, 동일 조건의 중복 안내 방지를 검사한다. 실물 기기·네이티브 Expo·Android 검증도 별도로 남아 있다.
