# 검색 시작 화면 개선 (2026-11-16)

## 변경

`feat/search-discovery-history`는 공통 UI와 홈 개선 커밋 `630a0f0`에서 분기했다.

- 최근 검색어 최대 8개를 기기에 저장하고 재검색·개별 삭제·전체 삭제 제공
- 제목·작가 검색과 AI 사서의 취향 기반 추천을 안내하고 공유 예시로 연결
- 검색어 지우기 버튼과 검색 중 중복 접수 방지
- 자동완성·전체 검색의 이전 요청 취소, 늦은 응답 무시, 언마운트 시 정리
- 로딩·결과 없음·조회 실패를 분리하고 실패 시 재시도 제공

최근 검색어는 성공적으로 응답한 전체 검색만 기록한다(0건 응답 포함). 자동완성은 기록하지 않는다. 공백·대소문자 차이를 정리하고 기기의 잘못된 저장값을 검증한다. 저장 작업은 읽기·쓰기·삭제 순서대로 처리해 늦은 저장으로 삭제한 항목이 되살아나지 않게 한다.

검색 화면은 `bookApi.searchBooks`의 `handleErrorLocally` 옵션으로 오류를 화면 안에서 처리한다. 기존 호출자의 전역 오류 알림은 유지하며, 취소된 Axios 요청은 전역 팝업을 표시하지 않는다. 최근 검색어는 로그인 계정이 아닌 기기 기준이다.

## 검증

실제 로컬 Expo 웹과 실제 도서 API로 확인했다. 도서 응답을 목으로 대체하지 않았다.

| 항목 | 결과 |
| --- | --- |
| 제목 검색 | `1984`, `모순`, `한강` 각각 20권 표시 |
| 기록 순서 | `[한강, 모순, 1984]` 확인 |
| 개별 삭제 후 새로고침 | `모순` 삭제 후 `[한강, 1984]` 복원 |
| 최근 검색 재실행 | `1984` 재검색 후 중복 없이 `[1984, 한강]`으로 이동 |
| 전체 삭제 후 새로고침 | 기기의 저장값 제거, 최근 검색 영역 사라짐, AI 진입 영역 유지 |
| 자동완성 | `해리 포터` 실제 미리보기 5권 표시, 최근 검색어는 변경되지 않음 |
| 결과 없음 | 존재하지 않는 검증용 검색어에서 결과 없음 안내와 AI 이동 버튼 표시 |
| AI 진입 | `짧은 에세이` 선택 → 해당 조건이 입력창에 표시. 뒤로 가면 검색 탭으로 복귀. AI 작업 접수는 실행하지 않음 |
| 반응형 | 320·390·1280px에서 문서 가로 넘침 없음. 1280px 화면의 콘텐츠 폭 640px 유지 |
| 자동 검사 | TypeScript·ESLint 경고 0, 테스트 21개, 공개 API 주소를 지정한 정적 웹 빌드 통과 |
| 시작 화면 | 실제 브라우저 번들 API 주소, 폰트 preload 제거와 swap 검사 통과 |

추가된 10개 테스트는 기록 검증·최대 개수·복원·삭제 순서·저장 실패 복구, 이전 요청 무효화, Axios 취소·로컬 오류 처리·기존 호출자 오류 알림 유지를 확인한다. Axios 실패는 테스트 어댑터로 검증했다. 실제 오프라인/503 상황에서 화면 재시도까지의 전체 흐름, 실물 기기·네이티브 Expo·Android는 추가 검증이 필요하다. 개발 중 Hot Reload에서 기존 EventSource 종료 경고가 관찰됐으며 검색 요청 오류와 별개다.

## 베타 웹 반영

코드 커밋 `992150b`를 Pages 배포 `024070d9`로 https://read-on-me-beta.pages.dev/search 에 반영했다. 공개 브라우저에서 최종 번들 `entry-ef9db3dd4c43789ecb479f83a3bfbbd7.js`, 실제 `1984` 검색 20권, 입력 지우기, 새로고침 후 최근 검색어 복원을 확인했다. 가로 넘침과 콘솔 error 로그는 없었다. iPhone 16 Pro / iOS 18.2 시뮬레이터의 실제 Safari에서도 공개 검색 시작 화면의 다크 모드·캐릭터·메뉴 배치를 확인했다.
