# UI 규격과 하단 메뉴 개선 (2026-11-16)

## 변경 범위

`feat/ui-consistency-navigation`에서 메인·검색·서재, 로그인·회원가입, AI 책 선택·비교, 책 상세, 알림과 팝업을 정리했다. 기존 에디토리얼 서체·테마·책갈피 캐릭터를 유지한다.

| 항목 | 공통 규격 |
| --- | --- |
| 웹 화면 / 폼 | 최대 640px / 최대 440px, 가운데 정렬 |
| 좌우 / 하단 콘텐츠 여백 | 24px / 32px + 필요한 안전 영역 |
| 제목 / 섹션 제목 / 본문 / 보조 문구 | 28/40, 20/28, 15/24, 12/18px |
| 일반 / 작은 버튼 / 아이콘 터치 영역 | 최소 48px / 44px / 44×44px |
| 하단 메뉴 | 아이콘 22px + 문구 13px, 각 칸 전체 높이 64px + bottom inset |
| 모서리 | 컨트롤 8px, 카드 12px, 대화상자 16px |

규격은 `designTokens.ts`와 `screenLayout.ts`, 버튼·입력·상태 표시는 `components/ui`에서 관리한다. 하단 메뉴는 링크와 `tabPress` 이벤트를 유지하며 선택 상태·키보드 포커스를 표시한다. 로그인·회원가입은 입력해도 남는 필드 이름, 도움말과 오류 문구를 사용한다. 다크 모드의 선택 버튼은 밝은 바탕과 어두운 글자로 표시한다.

AI 카드의 추천 이유를 좁은 표지 옆에서 카드 전체 폭으로 옮겼다. 추천 이유·근거가 검증된 경우에만 이유를 표시하는 기존 정책은 유지한다. 리뷰의 수정·삭제 메뉴는 명시적인 ‘리뷰 관리’ 버튼으로 열어 웹에서 버튼이 중첩되는 구조와 길게 누르기에 대한 의존을 줄였다. 읽기 상태 저장 중에는 버튼을 잠가 중복 요청을 방지한다.

## 실제 검증

로컬 Expo 웹 `http://localhost:8081`, 실제 Spring/AI API와 기존 테스트 계정으로 실행했다. API 응답이나 추천 후보를 목으로 대체하지 않았다.

| 검증 | 결과 |
| --- | --- |
| 320·390·1280px × 홈·검색·서재 9조합 | 가로 문서 넘침 없음, gutter 24px·제목 28px 일치. 1280px에서 화면 x=320, 폭=640 |
| 하단 메뉴 클릭 범위 | 세 해상도 모두 각 칸 높이 64px. 각 칸 좌상·우하 모서리 안쪽도 같은 탭의 hit target |
| 메뉴 이동 / 접근성 | 클릭, Enter, Space로 실제 경로 전환. 선택된 탭의 aria-selected 확인 |
| 로그인 / 회원가입 오류 | 실제 로그인 성공과 확인 후 홈 이동. 잘못된 가입 입력 4항목의 오류가 동시에 표시됨. 연령 선택 checked 상태 확인. 새 계정은 만들지 않음 |
| 일반 검색 | ‘1984’ 실제 결과 20권 표시 |
| AI 추천 1 | ‘마음이 편안해지는 소설 추천해줘’ → 1권, 추천 이유, 한 권 결정, ISBN 상세 이동 확인 |
| AI 추천 2 | ‘소설 추천해줘’ → 5권, 두 후보의 checked 표시, 비교 화면, 한 권 결정, 상세 이동 확인. 이유 없는 후보의 대체 안내도 확인 |
| 상세 / 팝업 | 기존 읽기 상태 표시, 빈 리뷰 제출 시 내용·별점 안내 확인. 홈 추천 기준 팝업의 표시·닫기 확인 |
| 홈 타이핑 회귀 | 4초간 이미지 21개(캐릭터 포함) 추가 0·제거 0, 문구 상태 18개, 첫 표지 top 368px 고정 |
| iOS Safari | iPhone 16 Pro / iOS 18.2 시뮬레이터를 실제 다크 모드로 설정해 홈·회원가입의 렌더링 확인 |
| 자동 검사 | TypeScript, ESLint 경고 0, 기존 테스트 5개, 공개 API를 지정한 정적 웹 빌드 통과 |
| 시작 화면 회귀 | 실제 브라우저 번들 API 주소 확인. 39개 폰트 preload 제거와 font-display swap 검사 통과 |

Chromium 검사 중 발견한 SVG의 `accessible=false` DOM 경고를 `aria-hidden`으로 수정했다. React Native Web/내비게이션의 기존 pointerEvents, 이미지 resizeMode, JS 애니메이션 fallback 경고는 남아 있다. 실물 기기의 노치·키보드·글자 확대, 네이티브 Expo 앱과 Android의 전체 흐름은 별도 확인이 필요하다. 실제 가입 생성·리뷰 저장/삭제·읽기 상태 변경은 이번 UI 검증에서 실행하지 않았다.

## 베타 웹 반영

Cloudflare Pages 배포 `4a2d5c03`을 https://read-on-me-beta.pages.dev 에 반영했다. 공개 HTML이 최종 브라우저 번들 `entry-9c59e46190b5b6a4ff110574869b46a2.js`와 새 메뉴를 제공하고 폰트 preload가 0개임을 확인했다. 공개 브라우저의 390px 화면에서도 메뉴 각 칸이 130×64px이고 선택 상태가 표시됐다. 공개 API로 ‘1984’ 검색 결과 20건을 확인하고 서재 탭 이동도 실행했다. 브라우저 콘솔 버퍼를 비운 이후 이 공개 검증 구간에서 error 로그는 없었다.


## 후속: 홈 제목 위치 보정

제목 글꼴 크기와 좌우 여백만 같아도 제목의 세로 위치가 같지는 않았다. 공통 헤더의 `alignItems: flex-end` 때문에 44px 버튼 옆의 40px 홈 제목이 y=44px에 배치됐고, 검색·비로그인 서재의 제목은 y=40px이었다. 기본 헤더 높이도 96px/92px로 달랐다.

공통 헤더를 위쪽 정렬로 바꾸고 제목 영역의 최소 높이를 공통 작은 버튼과 같은 44px로 맞췄다. 비로그인 상태에서 320·390·640·1280px × 세 탭 12조합을 재측정했다. 모든 제목이 y=40px, 헤더 안 x=24px, 영역 높이=44px로 일치하고 문서 가로 넘침은 없었다. 390px 이상에서는 헤더 높이도 모두 96px이다. 320px 비로그인 홈은 인증 버튼이 다음 줄로 배치되어 높이가 152px이지만, 제목 시작점은 동일하다. TypeScript·ESLint 검사도 통과했다.

헤더 위치 보정은 Pages 배포 `a5ef4e7b`로 베타 웹에 반영했다. 공개 브라우저에서 새 번들 `entry-210dc40f28ffa48a1d1675414e7da0db.js` 로드를 확인하고 640px 화면의 홈·검색·서재 제목 y=40px, 헤더 높이=96px를 재확인했다.
