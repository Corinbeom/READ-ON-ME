# 홈 추천 검증 · 2026-11-27

## 한 권 서재 176개 비교

검증 DB에 있는 갈피 도서 176권을 한 권씩 서재에 담았다고 가정했다. 두 방식에 같은 한글 키워드 최대 세 개를 주고 본인이 가진 ISBN을 제외한 첫 세 권을 비교했다. 비교 대상은 기존 공개 키워드 추천 함수와 새 홈 추천 함수다. 기존 홈의 인기 도서 혼합 방식과 실제 클릭률은 별도의 평가 대상이다.

| 지표 | 기존 키워드 추천 | 새 홈 추천 |
|---|---:|---:|
| 결과를 받은 서재 | 130 / 176 | 130 / 176 |
| 첫 세 권에 원래 책과 다른 유형이 포함된 서재 | 57 | 64 |
| 노출된 카드 중 원래 책과 유형이 같은 카드 | 276 / 359 (76.9%) | 264 / 359 (73.5%) |
| 한 번이라도 추천된 서로 다른 판본 | 110 | 115 |

도서 유형은 이야기책·실용서·교양서 등의 저장된 분류다. 이 표에서는 유형만 비교한다. 실제 홈 요청은 서재 전체에서 집계한 키워드를 최대 12개 사용하며, 같은 책을 두 권 이상 읽은 독자가 있을 때는 그 독자의 기록도 사용한다.

## 책을 대조한 사례

- 『우리나라 탐조지 100』의 첫 추천은 『뒷마당 탐조 클럽』이었다. 두 책에는 ‘조류 관찰’ 키워드가 있다. 다음에 나온 『여행의 이유』는 ‘여행’으로 연결된다. 두 번째 책과의 공통점은 여행이라는 더 넓은 주제다.
- 『구의 증명』에는 ‘사랑’, ‘애도’, ‘기억’이 붙어 있다. 첫 구현에서 ‘기억’을 공유한 뇌과학 책 『도둑맞은 뇌』가 두 번째에 나왔다. 하나의 넓은 단어만 겹치는 경우의 우선순위를 낮춘 뒤 첫 세 권에는 『애니가 남긴 것』, 『빛이 이끄는 곳으로』, 『이별 박물관』이 나왔다. 『애니가 남긴 것』과는 ‘애도’가 겹친다.
- 추천할 책이 없었던 서재는 두 방식 모두 46개였다. 서재를 한 권으로 제한한 평가이므로 실제 계정의 빈 결과 비율은 운영 데이터에서 별도로 확인해야 한다.

## 재현

검증 DB를 가리키는 `DATABASE_URL`과 그 DB의 `GALPI_REVIEWED_RELEASE`를 사용해 `BookAppAI`에서 `python -m tools.evaluate_home_picks`를 실행한다. 도구는 릴리스가 현재 입력 및 평가 기록과 일치하는지 확인한 뒤 저장된 태그로 계산한다.

## 기능 확인

- PostgreSQL 테스트에서 갈피 후보에 없는 성남 소장자료 한 권의 ‘경영’ 키워드로 추천이 생성되는 것을 확인했다. 빈 서재, 다른 독자만 근거인 경우, 소장 ISBN·세트 제외, 권한과 릴리스 불일치, 태깅 작업 미등록도 확인했다.
- Spring 테스트에서 두 권을 함께 읽은 독자, 한 권만 함께 읽은 독자, 읽고 싶은 책만 겹치는 경우를 구분했다. 전체 자동 테스트는 Spring 95개, AI 서버 250개, 프런트엔드 79개가 통과했다.
- 로컬 웹 빌드를 390px, 1280px에서 테스트용 API 응답으로 확인했다. 추천 기준 문구, 표지에서 같은 ISBN 상세로 이동, 뒤로 가기, 최근 본 책 위치, 빈 목록에서 서재로 이동, 오류 후 재시도, 비로그인 시 추천 요청 생략을 확인했다.
- React Native 컴포넌트 테스트를 iOS와 Android 설정으로 각각 실행했다. 관심사·다른 유형·다른 독자 추천의 기준 문구, 카드 터치 시 ISBN 상세 경로, 빈 결과의 서재 버튼, 실패 후 재시도를 확인했다. API와 라우터에는 테스트 대역을 사용했다.
- iPhone 16 Pro 시뮬레이터의 Expo Go에서 테스트 계정으로 로그인했다. 홈에서 추천 기준을 열고 『새가 머무는 숲』 카드를 눌러 같은 ISBN의 상세와 소개를 확인했다. 뒤로 간 뒤 다른 독자 기준 문구, 503 응답, 재시도 후 빈 결과, ‘내 서재 보기’로 서재가 열리는 것까지 확인했다. iOS와 Android 배포용 번들 생성도 통과했다.
