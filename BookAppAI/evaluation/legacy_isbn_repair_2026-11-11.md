# 기존 코퍼스 ISBN 교정 — 2026-11-11

## 근거와 적용 범위

로컬 개발 DB의 추천 가능 `LEGACY` 중 ISBN 검증에 실패한 13권을 조사했다. 모두 `1400…` 값이었다. [카카오 도서 검색 API](https://developers.kakao.com/docs/ko/daum-search/dev-guide)에 기존 값으로 `target=isbn` 조회를 보내자, 각 책의 **같은 응답 레코드**에 유효한 ISBN-10이 함께 있었다. ISBN-10을 ISBN-13으로 변환하고 제목·저자·출판사·표지가 기존 행과 모두 일치하는 경우에만 교정했다. 다른 판본의 ISBN을 제목만으로 가져오지 않았다.

교정 전 `book_corpus`의 대상 ISBN 충돌, `books`의 기존 값, `book_tagging_jobs`와 `corpus_ingestion_jobs`의 참조 행은 없었다. 미리 보기에서 13건 모두 `MATCH`였고, 적용 작업은 선택 행을 잠근 상태에서 원래 값과 대상 중복을 다시 확인한 뒤 한 트랜잭션으로 완료됐다.

적용 후 이전 값은 0행, 교정 값은 13행이다. `ACTIVE`·`LEGACY` 추천 가능 코퍼스에 ISBN 검증 실패 행은 0건이며 상태별 권수는 `ACTIVE 12 / LEGACY 956 / DISABLED 29`로 유지됐다. 적용 전후 근거와 복구 매핑은 각각 `/tmp/readonme-isbn-repair-preview-20261111.jsonl`, `/tmp/readonme-isbn-repair-applied-20261111.jsonl`에 있다. 이 표의 ID와 적용 결과는 로컬 DB에만 해당한다. 다른 DB에서는 ISBN·제목·상태를 다시 대조한 뒤 도구를 미리 보기부터 실행해야 한다.

교정 후 실제 `SF 소설 추천` 응답 5권의 ISBN은 모두 유효했다. 이전에 `1400000309490`으로 노출됐던 『플랫랜드』는 `9781127241347`로 반환됐다.

## 재발 방지

- `BookAppAI/tools/repair_legacy_isbn.py`는 선택한 `LEGACY` 행을 읽고 같은 카카오 레코드의 유효 ISBN을 검증한다. 기본값은 읽기 전용 미리 보기이며 `--apply`가 있어야 변경한다. 검증 실패나 대상 중복이 하나라도 있으면 선택 행을 변경하지 않는다.
- Spring 서재 저장 경로는 유효한 ISBN-13을 우선 사용하고, 카카오가 잘못된 13자리 값과 유효한 ISBN-10을 함께 준 경우 ISBN-10을 ISBN-13으로 변환한다.
- Expo의 `getIsbn13`도 같은 우선순위로 유효성을 확인한다. 검증 가능한 ISBN이 없으면 빈 값을 반환해 책 상세 링크를 만들지 않는다.

검증: FastAPI 테스트 144개, Spring 전체 테스트와 ISBN 관련 서비스 테스트, Expo 타입 검사 통과. Expo ISBN 변환 함수는 잘못된 13자리 값과 유효 ISBN-10이 함께 있는 경우 등을 포함한 4개 입력으로 직접 실행했다.

`main` 병합 후 로컬 API 연결 검증에서 카카오가 ISBN-10(`1127241346`)으로는 『플랫랜드』를 반환하면서 변환된 ISBN-13(`9781127241347`)으로는 결과를 주지 않는 것을 확인했다. Spring 상세 조회는 유효한 `978` ISBN-13의 첫 조회가 비어 있으면 대응 ISBN-10으로 다시 조회하고, 반환 레코드의 정규화 ISBN이 요청 값과 일치할 때만 저장하도록 보완했다. 수정 후 `/api/books/detail/9781127241347`은 200과 해당 ISBN을 반환했다. 테스트 계정으로 이 책과 AI 추천 결과 책의 상세 조회·서재 저장·서재 재조회도 확인했다. `SF 소설 추천`은 작업 성공 후 0권, `추리 소설 추천해줘`는 1권, `소설 추천해줘`는 4권이었다. 일반 소설 결과에 학습용 선집이 포함된 문제는 추천 품질 과제로 남긴다.

## 남은 범위

이 작업은 로컬 `book_corpus`의 13행만 교정했다. 다른 환경의 코퍼스와 이미 저장된 사용자 서재 도서는 별도 점검이 필요하다. 정상 ISBN이지만 잘못된 책을 가리키는 경우는 체크섬 검사만으로 찾을 수 없다.
