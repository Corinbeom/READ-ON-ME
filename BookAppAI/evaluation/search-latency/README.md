# 갈피 검색 응답 시간 개선 기록 · 2026-11-25

## 운영에서 관찰한 증상

배포 직후 부모와 자녀의 대화 예시를 묻는 요청 한 건은 등록부터 완료까지 30.76초였다. 작업 대기가 3.86초, 처리 시작부터 결과 저장까지가 26.90초였다. 첫 추천은 Gemini가 골랐다. 당시 로그로는 그 26.90초에서 DB와 모델의 소요 시간을 구분할 수 없었다.

## 수정과 측정 결과

기존 검색은 공개 가능 목록을 검사한 뒤 121권의 현재 필드와 색인을 책마다 다시 읽었다. 수정 버전은 요청 하나의 트랜잭션 안에서 현재 필드를 일괄 검증하고, 같은 입력 버전의 태그·벡터만 읽는다. 검색에는 방금 검증한 목록을 전달한다. 필드·정책 행의 공유 잠금과 후보를 모델에 보내기 직전의 권한 검사는 유지한다. 상세나 이용 가능 상태만 조회할 때에는 벡터 본문을 전송하지 않는다.

동일한 121권 로컬 PostgreSQL 복제본에서 운영용 AI 검색 핸들러를 호출했다. 첫 실행은 예열로 제외했다. 고정 실험은 쿼리 벡터와 모델 선택 동작을 고정해 외부 대기 시간을 제거한다. 각 버전 20회이며 P95는 오름차순 19번째 측정값이다.

| 고정 실험 | 운영 코드 3dcf8ea | 수정 코드 |
|---|---:|---:|
| 요청당 SQL 실행 횟수 | 387 | 25 |
| 공개 판정 및 색인 준비 중앙값 | 320ms | 89ms |
| AI 핸들러 전체 중앙값 | 1001ms | 148ms |
| AI 핸들러 전체 P95 | 1103ms | 172ms |

수정 후 색인 준비 시간에는 검색용 벡터 로딩까지 포함된다. 이전 코드는 이를 공개 판정 다음에 별도로 수행했다. 고정 실험에서는 수정 전후 모델에 도달한 후보 10권의 순서가 모든 실행에서 일치했다.

같은 질문으로 실제 모델까지 호출한 결과도 별도로 확인했다. 각 버전 3회이며 외부 공급자 상태에 따라 달라질 수 있다.

| 실호출 | 개별 AI 응답 시간(초) | 중앙값 | 질문에 맞는 첫 책 |
|---|---|---:|---:|
| 수정 전 | 4.02 / 4.22 / 7.53 | 4.22초 | 3/3 |
| 수정 후 | 6.46 / 3.67 / 2.16 | 3.67초 | 3/3 |

수정 후 실호출 세 건에서 최종 모델 순위 결정에 1.49~5.80초가 걸렸다. 이 단계가 다음 운영 측정에서 살펴볼 항목이다. 수정 전 실호출의 공개 판정 시간은 별도 수집하지 않아 CSV에서 비워 두었다.

검증 환경 시간에는 Spring의 대기열과 결과 저장, 화면 갱신이 포함되지 않는다. 운영의 30.76초와 측정 범위·실행 환경이 다르다. 운영 개선 폭은 배포 후 같은 범위에서 다시 측정해야 한다. [개별 측정값](measurements.csv)

## 추천 품질과 운영 확인 방법

고정 평가의 첫 결과 적합은 1차 18/18, 2차 18/18이었다. 적합한 책 한 권 이상은 각각 18/18, 18/18이었다. 가상 작가·수상명은 각각 2/2, 2/2 정상 빈 결과였다. 수정 코드의 검증 릴리스는 `88b54a13d7ea3869264a412050093e947ee584ac18d5628602a89643e8d55502`이다. AI 자동 테스트 234개가 통과했다. 이번 변경은 검증 환경에 적용했다. 운영 적용 시 서버 버전과 해당 릴리스의 평가 기록을 함께 전환해야 한다.

운영에서는 작업 ID로 `ai_search_jobs`의 등록·시작·완료 시각과 AI 컨테이너의 `reviewed_search` 로그를 연결한다. AI 로그의 `index_ms`는 공개 판정과 색인 준비, `embed_ms`는 질문 벡터 생성, `rerank_ms`는 모델 선택과 장애 대체를 포함한 최종 순위 결정 시간이다. `other_ms`에는 후보 선별, 추천 근거 읽기·저장과 커밋 등이 포함된다. 모델 호출이 발생한 요청과 대체 결과를 구분해 비교한다.
